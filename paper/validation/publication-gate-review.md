# 发布防线检查

本报告只验证发布工具的拒绝条件与来源约束，不代表论文或实验已完成验收。全部检查在 CPU 上执行；没有生成最终数据图、HTML 或 ZIP，也没有运行 GPU。

## 已补强的验收

- `validate_publication.py`、`record_capture.py` 与打包器采用显式异常，`python -O` 不会关闭检查。正文要求完整 8 个源文件、全部登记图位及所有已完成结果；带 `BF16` 等数字的控制块同样检查。知乎 Markdown 必须与完整源稿及当前图注逐字重建一致。
- 数据图必须由当前 8 个输入生成，7 张技术 SVG 与对应 PNG 均绑定文件散列；另有 17 张终端截图，合计 24 个登记图位。延迟输入要求当前 schema、有限输出、真实样本数及由未排序样本重算的 P50。跨 PyTorch/APXInf 入口不计算倍率；同 APXInf π0.5 比较须匹配权重、资产、入口、输入、种子、样本数、warmup、模型参数配置与已安装扩展身份。
- 五臂汇总除检查每臂 100 回合、每任务初态 10–19 和逐集配对外，还核验 15 个来源 JSON，并用当前 `compare_round` 重算全部汇总。运行 manifest 的五个 checkpoint 路径与各臂评测入口相连，源码与协议散列必须一致。
- HTML 构建保存完整源文件、图表、离线字体和构建器的清单。浏览器报告绑定当前 HTML、QA 脚本、图清单及全部 SVG/PNG，逐个检查图位、截图解码、公式数量和溢出；空图集、外部运行资源和失败后的旧通过报告均不能放行。
- 17 张运行截图必须有相同尺寸和图像散列。新图还要求 `accepted_not_black`、成功退出、人工内容复核、原始 capture sidecar 与 taskbar-only 裁剪清单的关联。本轮采用 15 张按当前规范重新捕获的截图与 2 张获准保留的 BF16 图；缺少完整质量与裁剪链的 `shot_verify` 已标为待重拍，不采用旧记录例外。两张 BF16 图须具有当前 Git 可验证的原始或公开仓库锚点，且与原始 JSON 一致。
- 打包每次重新执行全部验收，不能依赖旧的 `passed` 标志。拒收缺失或多余导出图、符号链接、权重/缓存/临时文件；复制必要的仓库外层证据和源码到 `project-inputs/`，保存路径映射和逐文件散列，写完整临时 ZIP 后才替换目标。

## 验证

移除旧 `shot_verify` 哈希豁免后，使用实际 GR00T 恢复环境，在 `CUDA_VISIBLE_DEVICES=''`、OMP/MKL 各 2 线程及 `-O` 下定向重跑发布防线 17 项、训练证据绑定 8 项，共 25 项通过，跳过、失败与错误均为 0。新增回归用例明确验证：旧图与旧日志的精确散列也不能绕过当前 capture sidecar 要求。日志、测试文件和检查时的源码身份见 `publication-guard-checks.json` 与 `training-publication-checks.json`；源码清单不表示逐行覆盖。

主测试 85 项和 frontier 10 项保留各自执行时的原始收据。它们附带的全局源码库存中，`validate_publication.py` 的散列已因本次门禁修复变化；未修改这些旧散列，也不把本次局部复核宣称为原 119 项完整重跑。运行 manifest 的 53 个默认实现文件不包含发布校验器，本次修复不改变训练或评测实现身份。

发布防线夹具覆盖文件变更、越界路径、结果占位、正文变更、初态重复或不匹配、非布尔结局、黑图、裁剪关联、计时样本、中断浏览器 QA、缺失本轮数据、旧通过标志与 SVG 远程资源。这些 CPU 拒收测试不等于最终论文通过验收；测试收据也不包含最终浏览器或打包检查。完成真实结果与截图后，应依次生成图、渲染 PNG、构建 HTML、导出 Markdown，再运行浏览器 QA、发布验证和打包，以最终字节对应的新收据为准。
